# CourseWeave v0.2.0 release notes

**Draft — not published.** The date, live public artifact verification, final
application commit, and compatible public course commit remain release-time
inputs. Public v0.1.0 is not compatible with schema-v2 courses.

CourseWeave v0.2.0 is planned as the first public application release for the
canonical schema-v2 course model and continuous JupyterLab learner guide. Agent
Harness Path remains independently versioned in
[`macayaven/agent-harness-path`](https://github.com/macayaven/agent-harness-path)
and usable without this application; its planned v0.2.0 course release is the
optional interface target.

## Highlights

- Deterministic schema-v2 course, progress, privacy, and state contracts replace
  the schema-v1 runtime used by public CourseWeave v0.1.0.
- One learner conversation continues across confirmed native lesson, notebook,
  video, source, and terminal activities, with visible lesson scope and explicit
  one-request workspace sharing.
- Predictions, authored checks and hints, optional protocols, reviewed learning
  memory, state inspection/export/reset/delete, restart, and recovery preserve
  learner control. Assistant output cannot complete work or mutate durable state.
- The compatible local pilot covered all fourteen Agent Harness Path modules,
  twelve notebooks, and two optional protocols. Rapid native navigation and
  early reader-link interaction were corrected before the final run.
- Canonical Author editing and reviewed suggestions are present, but the complete
  S01–S14 acceptance was a student trial. It does not establish new full-course
  teacher/Author evidence.
- A portable macOS student launcher starts with the provider off, prepares a
  fresh versioned study home, refuses cloud-synced or redirected owned paths, and
  supports deliberate hidden-input or environment-based provider selection.
- Source archives retain runnable examples, source CI, frontend locks and sources,
  release scripts and the top-level project guidance needed to reproduce builds.

See the [complete changelog](../../CHANGELOG.md) for the changes since v0.1.0.

## Learner install after publication

The release will own the macOS learner asset
`agent-harness-path-courseweave-0.2.0-macos.tar.gz`. It is not downloadable while
this document carries the Draft marker. After the release page lists that asset
and `SHA256SUMS`, learners follow the checksum-first terminal setup in the
[root README](../../README.md). The archive expands to one top-level directory,
`CourseWeave Student Pilot v0.2.0`, and contains the exact application wheel and
course archive accepted for this release.

The guided route needs macOS, uv and first-setup internet access. It needs no
source checkout, prepared receipt, Node, separate Jupyter installation or
provider. Provider use is always explicit and the supported bundle profile is
text-only. The Agent Harness Path native route remains independently usable.

## Compatibility and migration

- Schema-v2 courses require CourseWeave v0.2.0 or a compatible prerelease. Do not
  use the public v0.1.0 wheel with the planned Agent Harness Path v0.2.0 course.
- `courseweave migrate` previews a v1 manifest conversion. `--apply` requires a
  separate output and never overwrites the source. Ambiguous selectors and
  unsupported semantics remain reported for human review.
- Learner state is external and bound to course identity. Back it up before an
  upgrade. Legacy state import is a separate, explicit operation requiring
  reviewed coordinate mappings.
- Installation and upgrade must preserve existing notebooks and state. Use a new
  study/state directory when the course identity differs, and keep v0.1.0 plus
  its state available for rollback until the migration is accepted.

## Provider and privacy boundary

The learner route works without a provider. Provider use requires an explicit
provider and model, with a key entered through hidden input or deliberately
selected environment variables. The launcher does not read maintainer-specific
gateway custody. A configured provider or synthetic fixture
does not prove a successful live connection. Provider/gateway retention remains
separate from CourseWeave state reset/delete.
